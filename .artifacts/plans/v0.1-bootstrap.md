# Plan: amendment-atoms v0.1 Bootstrap

**Objective:** Replace the incorrectly scaffolded agent-domain schemas with correct amendment-domain schemas (proposal, amendment-set, rule) and seed 3 proposal atoms documenting real governance changes, then publish exports.

**Status:** In-flight

---

## Rationale

| Alternative | Pros | Cons | Verdict |
|---|---|---|---|
| Replace schemas in-place | Correct domain content in correct location | Requires overwriting existing (wrong) schemas | **Chosen** — schemas are wrong domain |
| Add proposal schema alongside existing | Avoids deletion | Leaves agent schemas confusing downstream consumers | Rejected |
| Keep agent schemas, add proposal as new type | No deletions | Contradicts ATOMS.yml atom_types; agent domain is not this catalog | Rejected |

The existing `schemas/atom-v1.json`, `composition-v1.json`, and `rule-v1.json` were scaffolded with agent-domain content (persona, tool-definition, capability-declaration, etc.) that does not match the catalog's declared purpose or `atom_types` in `ATOMS.yml`. They must be replaced.

---

## Scope

**Files to modify:**
- `schemas/atom-v1.json` — replace with proposal atom schema
- `schemas/composition-v1.json` — replace with amendment-set composition schema
- `schemas/rule-v1.json` — replace with amendment rule schema

**Files to create:**
- `.artifacts/plans/v0.1-bootstrap.md` (this file)
- `atoms/proposal/common-md-autonomy-v0.19.json`
- `atoms/proposal/code-md-delivery-cycle-v0.8.json`
- `atoms/proposal/atoms-spec-v1.1.0-grammar-atoms.json`
- `exports/catalog.json` (update with 3 atoms)

---

## Approach

1. Write plan (this file)
2. Replace `schemas/atom-v1.json` with proposal atom schema — typed by `change_type` enum
3. Replace `schemas/composition-v1.json` with amendment-set composition schema
4. Replace `schemas/rule-v1.json` with amendment rule schema (ordering, quorum, conflict-resolution, expiry)
5. Create `atoms/proposal/` directory with 3 seed atoms:
   - `common-md-autonomy-v0.19.json` — corrective amendment to approval keyword
   - `code-md-delivery-cycle-v0.8.json` — additive amendment for delivery cycle discipline
   - `atoms-spec-v1.1.0-grammar-atoms.json` — additive amendment introducing grammar atom class
6. Update `exports/catalog.json` with all 3 atoms
7. Commit, push, open PR, merge

---

## Testing strategy

- JSON files are well-formed (parseable)
- All proposal atoms include required fields: `schema`, `type`, `id`, `version`, `name`, `target_document`, `change_type`, `rationale`
- `exports/catalog.json` atom count matches files in `atoms/proposal/`
- Schema `$id` and `schema` const values match canonical domain `amendment-atoms.com`

---

## Risk assessment

| Risk | Mitigation |
|---|---|
| Overwriting wrong schemas breaks CI | CI validates against new schemas; seed atoms are written to pass them |
| `id` pattern in existing schema (`^[a-z0-9][a-z0-9-]{1,62}[a-z0-9]$`) not suited to slash-paths | New atom-v1 schema uses `^[a-z0-9][-a-z0-9/]*[a-z0-9]$` to allow namespaced IDs |
